二、作品介绍

2.1 研发背景与校园痛点

高校图书馆是师生自主研习的核心公共空间，长期面临突出的治理痛点：

  • 虚假预约与人情占座频发：学生线上订座后超时未至，造成“系统显示爆满，馆内空座大半”；或用书包、水杯长期“人走留物”恶意占座。
  • 人工巡查成本高、易起纠纷：管理员逐层核查费时费力，无法做到全天候闭环监管，缺乏客观的技术取证依据。
  • 中心化视频上传存在隐私风险：若将全馆监控全量上传至云端中心分析，不仅带宽算力开销巨大，还容易引发广大师生对人脸及隐私泄露的担忧。

2.2 核心创新与产品特色

“智座星野”创新采用“端侧轻量视觉AI + 时空状态机调度 + 自包含小程序架构”，带来革新性体验：

  • 全流程无感闭环：“选座 $ o$ 签到 $ o$ 暂离报备 $ o$ AI视觉在馆巡检 $ o$ 超时自动释放 $ o$ 违规惩戒”一气呵成。
  • 端侧边缘视觉推理：在前端浏览器/小程序本地沙盒内运行 MobileNet-SSD 模型，视频原始流绝不上传，充分保障师生隐私。
  • 单文件小程序极速开箱：作品整合为单个自包含 HTML，内嵌实拍巡视素材与时序标注数据，在无网、离线环境下依然可直接双击运行全套 AI 巡视与演示工具，极具可移植性与易用性。

三、AI 应用说明

3.1 轻量级深度学习目标检测模型

选用 TensorFlow.js + COCO-SSD（MobileNetV2 骨干网络）。模型总大小仅数兆字节，直接基于客户端硬件利用 WebGL / WebAssembly 实现硬件级并发推理：

  • 人员识别（person）：置信度阈值 ≥ 0.55
  • 遗留物品识别（backpack / handbag / laptop / book）：置信度阈值 ≥ 0.45
  • 帧率与性能：端侧实时帧率稳定在 25~30 FPS，响应时间小于 40ms。

3.2 复合空间“人-物-座”时空状态机研判算法

针对学生短暂起身上洗手间、打水等正常行为，算法设计了时序滑动窗口与暂离保护判定：

[目标座位区域判定逻辑] ├─ 区域内检测到 人员(person) ───────► 【正常就座 (ACTIVE)】 ├─ 区域内 无人员 且 无任何物品 ─────► 【座位空闲 (VACANT)】 └─ 区域内 无人员 但有背包/电脑等物品 ─► ├─ 学生已报备暂离且在时限内 ───► 【正常暂离保留中】 └─ 未报备暂离 或 暂离已超时 ────► 【触发占座告警 (GHOST_OCCUPANCY)】 └─ 开启3分钟缓冲倒计时，未回自动释放并计违约

3.3 离线与在线双通道巡查机制

  • 实况摄像头通道（Live Camera）：调用本地 WebCam，实时对自习桌进行动态目标画框检测与热力渲染。
  • 数字孪生实拍通道（Digital Twin）：小程序内置预采真实图书馆巡视视频片段（Base64编码）与时序空间坐标，断网状态下仍能 100% 完整复现 AI 巡视与告警处置。

5.1 端侧 AI 视觉状态机研判引擎（选自小程序）

// 计算预测边界框与座位预设 ROI 区域的重合度并研判状态
function evaluateSeatStatus(predictions, seatROI) {
    let hasPerson = false;
    let hasItems = false;
    
    for (const pred of predictions) {
        const [x, y, w, h] = pred.bbox;
        const overlap = computeOverlapRatio({x, y, w, h}, seatROI);
        if (overlap > 0.35) {
            if (pred.class === 'person' && pred.score >= 0.55) {
                hasPerson = true;
            } else if (['backpack', 'handbag', 'laptop', 'book'].includes(pred.class)) {
                hasItems = true;
            }
        }
    }

    if (hasPerson) return { status: 'occupied', label: '正常就座' };
    if (hasItems) return { status: 'ghost', label: '疑似占座(人走物留)', alert: true };
    return { status: 'vacant', label: '空座' };
}

5.2 后台 15 分钟超时未签到巡检守护线程（选自 app.py）

def background_scheduler_worker():
    """后台守护线程：每 20 秒扫描一次，判定开座后 15 分钟未签到违约"""
    while True:
        pytime.sleep(20)
        conn = None
        try:
            conn = sqlite3.connect(DB_PATH, timeout=30.0)
            cur = conn.cursor()
            threshold = (datetime.now() - timedelta(minutes=15)).strftime('%Y-%m-%d %H:%M:%S')
            
            cur.execute("SELECT id, user_id FROM reservations WHERE status = 'reserved' AND start_time < ?", (threshold,))
            for res_id, u_id in cur.fetchall():
                cur.execute("UPDATE reservations SET status = 'released' WHERE id = ?", (res_id,))
                cur.execute("UPDATE users SET violation_count = violation_count + 1 WHERE id = ?", (u_id,))
                cur.execute("UPDATE users SET is_restricted = 1 WHERE id = ? AND violation_count >= 3", (u_id,))
            conn.commit()
        finally:
            if conn: conn.close()
