二、作品介绍

2.1 研发背景与真实校园痛点

痛点 1：“空气预约，约了不来” —— 系统不提效，反而锁死公共资源

很多高校上线了纯预约系统，但“只管预订、不管履约”。学生随手抢座后因故未到馆；因缺乏自动惩戒和超时释放机制，系统显示全馆“满座”，馆内实际却大片闲置。想学习的同学找不到座位，公共资源利用率被“空气预约”大幅拉低。

痛点 2：“人情占座，人走物留” —— 传统治理靠腿跑，取证困难矛盾多

图书馆最常见的摩擦是“一本书、一个水杯占座一整天，人却不在”。管理员只能一层层楼徒步巡查，人工核验、人工登记、人工搬书，工作强度极大。不仅效率低下，在清理物品时极易与学生产生财产和人身纠纷。

痛点 3：传统方案“高成本、难部署、存隐私隐患”

传感器改造硬件成本高昂且难以维护；中心化监控若将全馆视频全量传至云端跑大模型，不仅带宽与算力成本极高，更引发全校师生对“人脸抓拍、行踪泄露”等个人隐私的严重担忧。且传统作品部署沉重，评委常因缺少环境而无法开箱体验。

2.2 通过什么方式解决痛点

“智座星野”团队采用“端侧轻量视觉AI + 严密规则状态机调度 + 自包含单文件架构”，打通无人化闭环治理：

校园治理痛点 传统模式局限 智座星野创新对策
占座治理靠人跑 扫码可代刷，人工巡查耗时易冲突 轻量化端侧视觉 AI 巡查：边缘识别“人-物-座”，精准识别“人走留物（书包/电脑）”，无需人工巡检，自动识别占座并释放。
约了不来没人管 无履约机制，座位被空气预约锁死 开座 15 分钟超时释放引擎：后台毫秒级巡回核验，超时未签到自动强制释放座位并记违约 1 次；累计 3 次自动限制预约。
系统沉重难部署 依赖特定数据库与网络环境，断网瘫痪 单文件小程序 + 24小时云端双模：单个 HTML（1.36MB）双击即开，内置实采素材，断网可测；同时部署在云端随时可用。
视频上云侵犯隐私 监控视频全量上传，学生担心隐私泄露 端侧 WebGL 边缘推理：在浏览器本地沙盒推理，原始视频流绝不上云，不存人脸特征，零隐私隐患。

    • 现场评测演示工具箱：勾选「演示加速（30秒模拟超时）」、一键生成超时未到记录、一键恢复标准演示数据。

2.4 突出核心优势（为什么非 AI 不可）

  • 打通屏幕预约状态与实体桌位真实情况的鸿沟：扫码、刷卡都无法防止“替人代扫”或“扫码后留下书包离开”。唯有计算机视觉，能客观、实时地回答“座位上到底是有真人，还是只有书包等占座遗留物”。
  • 真正的无人化履约闭环：摄像头输入 → 端侧检测（人/背包/电脑/书本） → 持续判定 → 占座告警 → 一键确认 → 释放座位 + 计入黑名单，非装饰性模块，直击业务本质。
  • 三通道素材源容灾设计，保证任何评测场景 100% 成功：
    • 内置模拟实拍（默认）：内嵌实采图书馆俯视监控视频与时序标注，无需网络与摄像头，断网双击秒开，稳定输出 100% 一致的高保真演示；
    • 本地素材上传：支持选取本地视频/照片在浏览器内跑真实模型推理；
    • 实时摄像头：连接电脑摄像头进行活体目标画框检测。
  • 单文件零依赖，开箱即用：单个 HTML 文件完整自包含，兼具极佳的便携性与实用性；同时云端 24 小时开机部署，手机随时可测。

三、AI 应用说明

3.1 核心算法与轻量化模型选型

围绕“智慧校园轻量化 AI 实用工具”定位，系统选用端侧深度目标检测网络：
• 推理引擎：Google TensorFlow.js，通过 WebGL 激活客户端 GPU 硬件加速。
• 目标检测模型：基于 MobileNetV2 改进的轻量化 COCO-SSD 深度卷积网络，体积仅数兆字节，在移动端和普通 PC 浏览器上均能稳定达到 25~30 FPS 的实时推理性能。
• 目标过滤与置信度阈值：人员（person）阈值 ≥ 0.55；随身物品（backpack / handbag / laptop / book）阈值 ≥ 0.45。

3.2 复合空间“人-物-座”时空状态机研判算法

系统在预设座位区域（ROI）建立目标空间交并比（IoU）时空关联模型：

[目标座位区域判定逻辑] ├─ 区域内检测到 人员(person) ───────► 【正常就座 (OCCUPIED)】 ├─ 区域内 无人员 且 无任何物品 ─────► 【座位空闲 (VACANT)】 └─ 区域内 无人员 但有背包/电脑等物品 ─► ├─ 学生已报备暂离且在时限内 ───► 【正常暂离保留中】 └─ 未报备暂离 或 暂离已超时 ────► 【触发占座告警 (GHOST_OCCUPANCY)】 └─ 开启3分钟缓冲倒计时，未回自动释放并计违约

3.3 零隐私风险与端侧边缘计算准则

模型直接在前端沙盒中运行，原始视频帧计算完即在内存中销毁，不存储人脸图像，更不向后端上传任何视频流，彻底打消师生对隐私泄露的顾虑。

五、源代码

5.1 端侧 AI 视觉巡查与占座状态机引擎核心源码（选自小程序）

// 计算检测边界框与目标座位区域 ROI 的重合面积比例 function computeOverlapRatio(box, roi) { var x1 = Math.max(box.x, roi.x); var y1 = Math.max(box.y, roi.y); var x2 = Math.min(box.x + box.w, roi.x + roi.w); var y2 = Math.min(box.y + box.h, roi.y + roi.h); if (x2 <= x1 || y2 <= y1) return 0; var interArea = (x2 - x1) * (y2 - y1); var roiArea = roi.w * roi.h; return interArea / roiArea; } // “人-物-座”时空复合状态机研判 function evaluateSeatStatus(predictions, seatROI) { var hasPerson = false; var hasItems = false; predictions.forEach(function (pred) { var box = { x: pred.bbox[0], y: pred.bbox[1], w: pred.bbox[2], h: pred.bbox[3] }; var overlap = computeOverlapRatio(box, seatROI); if (overlap > 0.35) { if (pred.class === 'person' && pred.score >= 0.55) { hasPerson = true; } else if (['backpack', 'handbag', 'laptop', 'book'].indexOf(pred.class) !== -1) { hasItems = true; } } }); if (hasPerson) { return { state: 'OCCUPIED', label: '正常在座', alert: false }; } else if (hasItems) { return { state: 'GHOST_OCCUPANCY', label: '疑似占座(人走物留)', alert: true }; } else { return { state: 'VACANT', label: '空座', alert: false }; } }

5.2 预约冲突排他性检测与防分身占座校验核心源码（选自小程序与后端）

// 检查时间段是否发生重叠交叉 function isTimeOverlapping(startA, endA, startB, endB) { return !(endA <= startB || startA >= endB); } // 核心预约校验：座位防超卖 + 个人防多定 + 3次违约封禁限制 function validateReservation(db, userId, seatId, startTime, endTime) { var user = db.users.find(function(u) { return u.id === userId; }); if (!user) throw new Error('用户不存在'); if (user.isRestricted || (user.violationCount || 0) >= 3) { throw new Error('您已累计违规达 3 次，系统已限制预约权限，请联系管理员！'); } // 1. 检查目标座位在该时间段是否已被抢定 var seatBusy = db.reservations.some(function(r) { return r.seatId === seatId && ['reserved', 'active'].indexOf(r.status) !== -1 && isTimeOverlapping(r.startTime, r.endTime, startTime, endTime); }); if (seatBusy) throw new Error('手慢了，该座位该时间段已被预订！'); // 2. 检查该学生同一时间段是否已有其他预约（防分身占座） var userBusy = db.reservations.some(function(r) { return r.userId === userId && ['reserved', 'active'].indexOf(r.status) !== -1 && isTimeOverlapping(r.startTime, r.endTime, startTime, endTime); }); if (userBusy) throw new Error('您在该时间段已有其他预约，一人不可同时占多个座位！'); return true; }

5.3 15 分钟超时未签到自动违规巡视守护引擎（选自小程序与后端）

// 守护调度巡视：开座后 15 分钟未签到自动强制释放并计违规 function runTimeoutInspection(db, nowTimestamp, isDemoFast) { // 正常模式为 15 分钟（900秒），演示加速模式为 30 秒 var timeoutThreshold = (isDemoFast ? 30 : 900) * 1000; var changes = []; db.reservations.forEach(function (res) { if (res.status === 'reserved') { var startTime = new Date(res.startTime).getTime(); if (nowTimestamp - startTime > timeoutThreshold) { // 超时未到：强制将状态置为超时释放 res.status = 'timeout_released'; // 找到该学生累计违规次数 var student = db.users.find(function(u) { return u.id === res.userId; }); if (student) { student.violationCount = (student.violationCount || 0) + 1; if (student.violationCount >= 3) { student.isRestricted = true; } } changes.push({ resId: res.id, studentName: res.userName, violations: student ? student.violationCount : 1 }); } } }); return changes; }
